# Civ-Sandbox：开放式人工历史模拟器

`civ-sandbox` 不再模拟一组预先命名的文明游戏动作，也不再沿固定时代和科技树推进。它运行一个更小但完整的闭环：自主 Agent 提出开放计划与开放事件，compiler 把提案约束为通用物理操作，`WorldEngine` 再根据当前世界状态决定能否执行、需要多久、产生什么结果，以及触发哪些副作用。

默认场景从公元前 230 年的战国七雄开始。此前的历史是各国共同记忆，此后的道路完全开放：秦国不保证统一，六国也不保证灭亡。人类、国家、粮食和铁料都只存在于场景数据中，底层引擎仍没有 `Earth`、`human`、`wheat`、`iron` 等专用逻辑，也没有固定时代或科技树。

原先的非地球智慧碳基生命开局仍可通过 `--scenario open-origin` 运行，用来验证底层没有被中国历史写死。

## 最小架构

```text
Agent / LLM
  │  任意中文目标、假说、制度与事件因果
  ▼
OpenPlan / OpenEvent
  │  语法检查、数值边界、守恒声明、稳定 ID
  ▼
PlanCompiler / EventCompiler
  │  通用 primitive 或因果状态增量
  ▼
WorldEngine
  │  资源、质量、空间、人口、能力依赖、工期、风险检查
  ▼
World state + 动态 knowledge graph + 中文编年记录
```

`OpenPlan` 没有动作类型枚举。计划可以叫“修建多孔缓流层叠体”“建立随机抽签的照料组织”或任何尚未出现过的名称，并可组合任意数量的步骤。`OpenEvent` 同样没有灾害或事件类型枚举，它只要求给出因果说明、持续时间、地点变化和模拟边界上的资源输入输出。

引擎内部仍有一组很小的 `PrimitiveKind`：`acquire`、`transform`、`construct`、`relocate`、`research`、`communicate`、`organize`。这些词不是历史行动菜单，而是类似物理指令集的通用操作。新的历史行动由它们的参数、对象和组合产生，不需要为“修坝”“信用制度”或“驯化某种生命”新增 enum。

## 因果与物理边界

`PlanCompiler` 从规模推导劳动量和工期，并拒绝非有限数值、过大效果和直接违反产出上限的转换。`WorldEngine` 才有权修改状态，它会再次检查实际库存、地点连通性、人口协作能力、材料质量、知识能力和前置知识。

事件可以改变任意已有环境属性，但资源变化必须满足全局质量收支。来自模型边界外的输入和流向边界外的输出必须显式记录。事件会按持续时间逐纪施加，不会瞬间改写最终状态。

研究成功后才会创建 `KnowledgeNode`。每个节点保存前置节点、观察证据、获得的能力和 failure modes，因此知识图谱由历史中的实际提案动态长出。知识风险会在相应能力被使用时重新参与结算，而不是只在“发明”一刻出现。

每种生命可以用 `metabolic_needs` 声明自己的通用资源 tag 与单位需求，因此底层不需要假定人类饮食。环境资源不会在后台凭空恢复，任何来自模拟边界外的补充都必须由带 `external_inputs` 的开放事件记账。项目可能失败，环境可能恶化，迁移可能受阻，组织也可能制造新的紧张。当人口足够多而凝聚度长期过低时，社会可能带着按人口比例分配的资源和继承知识分裂为新社会。引擎没有胜利条件，也不会保护任何社会免于停滞、分裂、崩溃或灭绝。

## 账本模式（默认，开放知识提案）

单次调用的「无约束大模型」模式有一个绕不开的问题：模型读过我们这个世界的两千年史，让它「推演」，它会把已知的结局换个名字写回来，技术按现实顺序整体提前，秦齐楚的身份两千年不散，华夏之外只是资源产地。账本模式把「决定发生什么」从模型手里拿走：

- 每一纪先由种子随机数结算外生冲击：各区域的气候冷暖、疫病是否爆发并沿商路传播。
- 九个宏观区域（黄河、长江、岭南南洋、草原、西域中亚、印度、西亚地中海、非洲、美洲）用同一套状态与同一套规则，没有主角。
- 模型只做两件事：替每个区域的政权提出本纪意图（研究、改制、战争、营造），以及在结算之后把账本写成纪事，不得增删事实。九个区域的提案并在一次调用里完成（各区域只见自己的可观察状态与邻区情报），每纪两次调用，全程二十三纪四十六次，一个额度窗口足够跑完；`ledger_config.json` 的 `llm.batch_regions` 设为 false 可退回每区域一次调用。
- 研究不再从科技菜单里选（`open_ledger_engine.py`，默认引擎）：模型要写出问题、假说、可失败的试验、机制与自由语言的预期后果，`from` 只列真正用到的既有知识；引擎按当地城市化、识字率与财政结算成败，成功后把后果按关键词投影到承载力、军力、商贸、识字、研究、卫生、航海这几个宏观变量上（投影结果记入账本的 `macro_projection`，可以核对）。这一步是一条已知的暗道：模型的措辞会影响它拿到哪种加成。
- 引擎依 `ledger_config.json` 中的速率结算收成与人口（承载力）、战争（军力、后勤、地形）、财政恢复、正统衰减、制度僵化，以及每个政权的压力：超过阈值就按概率解体、被兼并或被新集团取代，没有谁受保护；政权倒下时账册可能散佚，知识随之丢失。
- 知识是一张图：观察、原理、工艺三类节点，每个新节点必须写出依赖的既有节点，前置不在本区域账上的研究只会被记为未竟的探索；知识沿商路扩散，也只在前置齐备的地方落地；远洋接触后两边同时面对病原与技术的双向交换。
- 新政权由模型命名，名字对照 `forbidden_names` 剔除真实历史中的国名与人名；模型没回应时用引擎自造的名字。
- 远洋首次接触即刻结算一次「处女地疫病」：两边各以六成概率疫死一批人口并记入账本，而不只是留下一句「病原交换」。

所有速率、开局状态、纪的划分和禁用名单都在 `ledger_config.json` 里，改配置，不改提示词。

```bash
# 默认：账本模式，二十三纪，公元前230年至2026年
python3 main.py --seed 2026 --output .artifacts/china-ledger-history-2026.md

# 只跑前四纪看小样
python3 main.py 4

# 不接模型，用离线启发式提案与模板纪事跑通全程（确定性，用于测试与校准）
python3 main.py --no-llm
```

产物是一份 Markdown 通史（每纪一节，末附史官论赞、知识谱系与政权谱系）和一份同名的 `.ledger.json` 账本，记录每一条事件与终局状态，可以逐条核对纪事有没有越出账本。

每完成一纪，引擎把整个运行状态（含随机数状态与写检查点的引擎类名）写到输出文件旁的 `.checkpoint.json`。模型额度用尽时（agy 返回 quota 错误）引擎在纪的边界停下并退出码 2，而不是用模板把剩下的历史糊完；额度恢复后加 `--resume` 从断点续跑。离线（`--no-llm`）时续跑结果与一次跑完逐字相同；接模型时只保证账本连续，模型的回答本身不可复现。由另一个引擎写下的检查点会被拒绝续跑，避免把两套规则拼成一本书：

```bash
python3 main.py --seed 2026 --output .artifacts/china-ledger-history-2026.md --resume
```

## 运行

以下为其余三种模式。`--mode open-world` 是单次调用的开放提示词模式，`--mode real-history` 沿真实朝代走，把兼并决战、朝代更替、科技跃迁与制度鼎革都交给模型的宏大叙事，推演公元前230年至公元2026年的全景通史。两者都不受账本约束，产物是叙事而不是可核对的账：

```bash
# 开放提示词模式，前 8 纪
python3 main.py 8 --mode open-world

# 真实历史全景模式，指定随机种子与输出文件
python3 main.py 23 --mode real-history --seed 2026 --output .artifacts/china-unbounded-history-2026.md
```

如果需要切换到基于物理基元约束与因果裁定的经典离线沙盘模式，可以显式指定 `--mode classic`：

```bash
# 运行经典物理基元沙盘（战国七雄场景）
python3 main.py 12 --mode classic

# 运行通用外星生命开局
python3 main.py 12 --mode classic --scenario open-origin

# 显式使用确定性离线启发式规划器（完全按 seed 重放）
python3 main.py 12 --planner heuristic
```

这两种叙事模式优先使用本机已登录的 `agy`（`gemini-3.7-flash-high`），随后检测 `codex` 与 `claude`；无可用 CLI 时退回离线模板。账本模式只用 `ledger_config.json` 里配置的那一个工具，额度用尽时停下而不是退回模板。

`heuristic` 模式的提案和世界结算共用本地 `random.Random(seed)`，因此相同 seed 会得到完全相同的状态与中文记录。每一纪的 `EpochRecord` 都保留原始 `OpenPlan` 与 `OpenEvent`；第一版尚未提供把这些提案写入 replay tape 文件的 CLI。

## 第一版边界

当前物理层使用带单位质量的标量资源账本。它能检查取得、输运、转换和事件边界流的质量收支，但还没有元素组成、反应热力学、连续空间或流体方程。因此“符合物理规律”在这一版意味着提案不能超出已建模资源、空间、人口、工期、能力依赖和标量守恒约束，并不意味着它已经能证明任意新材料在真实化学上成立。

当前迁移 primitive 只支持社会整体迁移。社会分裂由低凝聚度的因果结算产生，而不是把部分迁移伪装成分裂。外部 LLM 提案会保留在内存中的 `EpochRecord`，但 replay tape 的文件导入导出仍是后续工作。

比较多个 seed：

```bash
python3 compare_seeds.py --seeds 0,1,2,3,4,5,6,7 --epochs 24
```

该命令列出各 seed 形成的知识、结构、组织、迁移终态、事件与副作用，并检查是否存在所有 seed 共有的知识序列或固定现实时代词。

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

```text
ledger_engine.py      账本引擎：规则与骰子结算，模型只提案与记述，检查点与续跑
open_ledger_engine.py 默认引擎：在账本引擎上放开研究提案（问题、假说、试验、机制）
ledger_config.json    账本模式的全部速率、开局、纪的划分与禁用名单
open_law_engine.py    单次调用的开放提示词叙事模式
unbounded_llm_history.py 真实历史全景叙事模式
models.py             开放计划、开放事件、世界状态与知识图谱
scenarios.py          战国末年与通用生命开局数据，不侵入底层引擎
plan_compiler.py      开放计划到通用 primitives 的确定性编译
event_compiler.py     无类别事件的因果与数值检查
world_engine.py       唯一能修改世界状态的确定性执行器
llm_backend.py        LLM 接口与可重放的离线提案器
engine.py             创世、逐纪调度、中文编年记录与快照
compare_seeds.py      多 seed 分叉检查
tests/                守恒、因果、风险、重放与分叉测试
legacy/               重构前的固定时代与固定动作实验
.github/workflows/    CI：两个 Python 版本跑测试，并离线跑三纪账本冒烟
```
